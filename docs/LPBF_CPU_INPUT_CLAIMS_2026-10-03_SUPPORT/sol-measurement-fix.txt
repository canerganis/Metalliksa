## Verified defect and changes

Existing UI created seven current-simulation conditions for absent/manual measurement conditions, and reduced every explicit supplied vector to seven fields. Actual Python `measurement_evidence` requires exactly 22 PROCESS_KEYS and rejects incomplete vectors (`python/lpbf_evidence.py:8-11,23-52`; validation called by `python/lpbf_simulation.py:243-245`). This was a frontend submit-contract failure; an active successful false-matched calibration factor was **not** demonstrated.

The tested `measurementSubmission` builder now drives the real component submit path:
1. Conditionless replicate/manual rows omit processVector; backend returns unverified and withholds calibrationFactor (`lpbf_simulation.py:1107-1113`).
2. Explicit complete 22-field vectors are retained unchanged. Partial/malformed/extra-key/type-invalid vectors produce actionable local errors. Definite equality stays with the worker's resolved inputs; preview detects only differences in supplied known controls and never claims exact matching.
3. Raw JSON width/depth and uncertainty must be finite numbers, excluding bool, numeric strings, null and containers. This agrees with backend exact int/float, non-bool checks; manual HTML numeric text is explicitly converted and separately checked for finite positive dimensions/nonnegative uncertainty.
4. Allowed replicate fields are exactly width_um, depth_um, source, processVector, uncertainty_um, independentHoldout, matching backend required/optional sets. Unknown metadata/typos are rejected with field names instead of being dropped. Nested uncertainty permits exactly width_um/depth_um; extras are named and rejected, missing values fail numeric validation.
5. Supported dimensions, source/specimen, uncertainty and user-declared holdout semantics remain available. Mixed batches with conditionless and explicitly complete vectors retain known supplied values. Backend/source flags, material normalization, calibration application, numerical thresholds and physics were not edited.

Frontend explicitly rejects supplied null processVector/uncertainty and requires supported strategy/nonblank material; Python treats null optional values as absent and checks resolved equality instead. This intentional stricter local input guidance never invents evidence.
